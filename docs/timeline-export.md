# 分集剪辑与成片导出

入口：短剧项目 → 选择分集 → **剪辑与成片**。需要服务端工作区、现有 CPU worker 和私有素材存储。模型适配器仍关闭，不需要模型 API 密钥。

## 操作闭环

1. 在分镜中采用图片或视频，点击“导入已采用镜头”；也可以“添加上传镜头”，直接上传或选择素材库文件。导入保留采用候选的引用快照，同一候选重复点击不会再次追加，后续更换采用版不改已有剪辑。
2. 拖动手柄排序，或使用上下移按钮；键盘聚焦手柄后按空格、方向键、空格。选择镜头设置裁剪入点、时长和原声音量。图片按设定时长停留，视频不足时定格最后一帧；原声不足部分静音。
3. 添加配音素材，设置音频裁剪入点、起点、时长和音量。时间基准可绑定镜头，也可使用全片绝对时间；绑定镜头的配音和字幕随调序移动。配音裁剪必须位于真实文件时长内，越界合成会明确失败。
4. 添加中文字幕，填写时间和文字。字幕不允许重叠，烧录到 MP4；也可下载当前草稿对应的 SRT。首期手动填写文字，不进行自动转录。
5. 保存剪辑获得版本号，然后“生成成片预览”。后台冻结版本、入队合成；关闭页面不影响任务执行。预览是最终归档 MP4，下载使用同一文件。修改后，旧预览显示版本提醒，需保存并生成新版。
6. 任务中心显示合成阶段，生成历史包含成片，素材库可查找下载文件。从成片任务返回会定位到对应分集、剪辑页和该次合成记录；刷新保留当前分集与页签。也可把成片追加到时间线再次剪辑。

草稿缓存在当前标签页 sessionStorage，切换分集/项目页签后可恢复；服务器保存才提供引用保护和跨设备持久性。项目 revision 与时间线 version 检查防止覆盖旧版本，冲突时需要恢复服务端版本后重新编辑。删除镜头同时移除绑定的字幕/配音，全片绝对时间轨不自动移动。

## 部署

Web 与 worker 仍使用同一数据库和私有存储。**Web 和 worker** 均需 FFmpeg/ffprobe 和相同的中文字体：Web 用于受限波形分析及字幕 PNG，worker 用于最终编码。Linux 可使用发行版的 ffmpeg、fontconfig、fonts-noto-cjk；macOS 可使用 Homebrew ffmpeg 和系统中文字体。选用的 FFmpeg 需包含 libx264、AAC 编码和 overlay、concat、amix、xfade、acrossfade 等过滤器，首期不依赖 libass/drawtext。

```dotenv
# 可不填，此时从 worker 的 PATH 解析
FFMPEG_PATH=/usr/bin/ffmpeg
FFPROBE_PATH=/usr/bin/ffprobe
RENDER_FONT=Noto Sans CJK SC 32
# 可选：管理员指定字体文件；不接受用户上传字体路径
# RENDER_FONT_FILE=/absolute/path/to/font.otf
```

安装依赖后重启 worker；Web 服务端代码变更后同时重新构建并启动 Web。缺少编码器、工具或字体会使合成失败；任务提示检查配置，不会伪造成功。已有健康检查覆盖数据库、文件存储、worker 和队列，尚未增加 FFmpeg/字体专用启动探针。

合成从私有存储复制当前账号的素材到临时目录，仅开放本地媒体协议及指定输入格式；不向 FFmpeg 传用户 URL。临时文件由正常成功、失败、取消路径清理，子进程退出后再清理文件。整机断电或 worker 被 SIGKILL 后仍可能遗留临时目录，需由部署侧清理过期 `aivideo-render-*` 目录；不要清理正在运行的任务目录。

## 限制与失败恢复

- 固定 30 fps，横屏 1280×720、竖屏 720×1280、方形 720×720，保持画面比例并补黑边。
- 每集最多 100 段、10 分钟、20 段配音、200 条字幕；每条字幕最多 300 字符。
- 输入画面不超过 4K 像素量，单任务唯一输入总量不超过 1 GB；成片不超过 100 MB；合成限时 8 分钟。沿用上传限制：图片 20 MB、音频 30 MB、视频 100 MB。
- 使用当前单任务 worker，分段串行编码、限制 FFmpeg 线程；长片实际速度依赖 CPU。已验收 10 分钟、100 镜头、20 段配音、200 条字幕的固定样例，见下方专项报告；不等于所有输入格式的性能上限。
- 同一幂等键与内容不会重复建任务。取消会终止编码并阻止发布输出；不同账号不能提交或读取彼此素材。
- 输出文件完成私有归档后，素材记录与任务成功状态在同一事务发布；任务重复执行不产生第二个输出。
- 成片失败可从任务详情重试，继续使用冻结版本。归档失败重试会重新编码该版本；不调用任何模型。已有 `archiving` 状态也可重新执行恢复。
- 已有实时草稿预览、交叉淡化/擦除转场、配音波形与字幕样式。尚未提供调色、动画关键帧、自动转录、口型对齐、多字幕层、4K 输出或工作流合成节点。

自动化使用独立 `aivideo_test*` 数据库和本机私有存储。新增测试真正编码测试图、测试视频和合成音，而不是仅断言任务状态；不使用真实模型 API。

最终验证：53/53 单元测试、46/46 服务端及 HTTP 测试（无跳过）通过；生产 build、lint/类型与边界、format、62 项固定源码哈希校验通过。服务端完整回归用时 46.70 秒，同时覆盖原有监控、备份恢复和任务/工作流链路。

- 单元：导入去重、调序后的音频/字幕绝对时间、SRT、移除镜头、范围/重叠拒绝、冻结版本和引用保护。
- 服务端：ffprobe 校验实际 H.264/AAC 文件、时长与尺寸；解码采样验证镜头颜色顺序、中文字幕像素和配音在指定区间出现。
- 失败路径：跨账号/素材类型/版本拒绝、幂等重复执行、取消排队和正在执行的合成、非法裁剪不产出、模拟磁盘归档失败及重试、持久化 archiving 状态恢复。

本机“验收 · 末班地铁”项目保留操作样例，媒体为纯色测试图、测试色卡和合成音。真实模型效果、真机 Safari、远程存储与目标部署环境不在本次验收证据内。


## 实时预览、波形、转场和字幕样式

- 上方“实时多轨预览”直接播放当前草稿，无需保存、排队或模型 API。画面、原声、配音和字幕共用 30 fps 时间轴；支持播放/暂停、进度定位、逐帧、回到开头。选择时间线镜头或“定位此配音”“预览此字幕”可定位。修改剪辑、波形裁剪或切到后台标签会暂停；素材缓冲会暂停时钟，超时提示重试。
- 播放器仅保留当前过渡所需画面和下个镜头；播放时独立时钟订阅不会每帧重绘整个编辑器，暂停后停止连续刷新。使用浏览器原生媒体解码与音量控制。画面在 sRGB Canvas 上合成；预览与导出共用固定混音余量，单声道左右声道映射一致。不同设备的解码、音量策略仍需实测，真机 Safari 尚未验证。
- 波形复用 wavesurfer.js **7.12.12** 的渲染器和 Regions 插件。阴影是音频源的采用范围，拖动两端裁剪或整体平移；点击波形定位草稿，时间字段提供键盘替代。前端按需加载库，服务端 FFmpeg 提取 8 kHz 单声道并聚合为每秒 50 个峰值，浏览器不解码整段 PCM。波形分析限源文件 10 分钟、30 秒超时、2 个并发；内存缓存最多 24 项，临时文件清理。超长/无声/损坏文件显示错误，可重试或继续使用时间字段。
- 在第二个及以后的镜头选择“入场转场”：硬切、交叉淡化、向右擦除，最长 3 秒。转场占用相邻镜头重叠区，所以会缩短全片时长；例如 2 秒 + 2 秒镜头，0.5 秒转场后总长 3.5 秒。单镜头入/出转场合计必须小于镜头时长。原声线性交叉淡化；额外配音按自身时点和音量混合。重新排序成为首镜头时自动移除其入场转场，其余转场保留并重新校验；字幕碰撞需要调整。
- 字幕可设置字号（20–80 输出像素）、文字颜色、底色及不透明度、顶部/居中/底部、左右/居中对齐与粗体，提供三个预设。每条字幕独立保存。Web 与 worker 共用 `server/src/caption.ts` 的 Sharp/Pango PNG，保证相同字体环境下换行、位置和样式一致。SRT 仅保存文字和时间，不保存外观；外观烧录到 MP4。
- 导出仍冻结已保存版本：CPU worker 先串行规范化镜头，再以两个输入逐个生成过渡区，最后拼接、混音、叠字幕。中间音轨使用 PCM，最终仅编码一次 AAC，避免转场处多轮有损音频编码。最大合成时间、输入总量、取消和归档规则沿用原底座。
- `/api/production/caption-preview` 校验会话、Origin、尺寸和样式白名单；`/api/workspace/assets/:id/waveform` 在读取缓存前校验账号和素材所有权。没有公共素材地址或任意 FFmpeg 过滤器/路径输入。

新增主要文件：`features/timeline/timeline-preview.tsx`、`playback-clock.tsx`、`audio-waveform.tsx`、`caption-style-editor.tsx`、`server/src/caption.ts`、`server/src/waveform.ts`。旧时间线缺少转场与样式字段时保持硬切和经典白字，无数据库迁移。


本轮增量验收：55/55 单元、50/50 服务端与真实 HTTP 测试，无跳过；lint、生产 build、format、62 项来源哈希通过。桌面与 390/320 CSS 像素实际操作覆盖双配音播放、转场逐帧、波形拖动裁剪与点击定位、字幕预设、保存与 MP4 下载。修复了预览画幅被高度挤压的问题，并在暂停时停止连续刷新。保留项目“全链路验收 · 雨夜来信”的第二集：v4 为 5 秒、v5 为 4.9 秒、复用 v5 后的 v6 为 6.4 秒，下载文件经 ffprobe 确认为 H.264/AAC 720×1280，中文样式抽帧已检查。桌面和窄屏均无页面横向溢出或相关控制台错误。此段为上轮验收记录；本轮已增加最长固定样例的实测，真机 Safari/Android 与部署环境仍未验收；所有模型 API 继续关闭。


## 十分钟一致性专项验收

基线结果见 [2026-10-15 专项报告](timeline-acceptance-2026-10-15.md)，后续资源与弱网增量见下一节。基线增加配音/字幕每页 5 条、秒数精确定位、字幕预取、统一混音余量与 SDR 色彩合成；修复长片预览时钟累计落后。PQ/HLG HDR 输入需先转换成 SDR，当前没有 HDR 色调映射。

部署仍是 Web、现有 CPU worker、PostgreSQL 与私有文件存储；FFmpeg 还需支持 `colorspace`、`setparams`、`pan` 过滤器。专项报告记录实际资源峰值，不能把开发机测量当成目标服务器容量保证。

### 2026-10-16 内存与弱网补充

最终拼接的视频和字幕输入现在也显式限制为单线程解码，输出继续使用两个编码线程。相同的 600 秒、100 镜头、20 段配音、200 条字幕样例，最终 FFmpeg 阶段的峰值 RSS 从 1,378 MiB 降到 518 MiB（约降低 62%），输出 MP4 的 SHA-256 完全相同。没有改变分辨率、帧率、编码质量、转场或混音规则，也没有增加服务。

完整渲染另以 Node 堆上限 256 MiB、FFmpeg 约 1.5 核 CPU 时间配额、导出进程树 768 MiB RSS 看门狗进行本机试验：415 秒完成，进程树峰值 696 MiB，输出 600 秒 / 18,000 帧 / 70.65 MiB，文件哈希仍相同。看门狗以约 100 ms 间隔采样并在超限时终止测试进程；它不是系统内存隔离，CPU 配额也不是实际低配服务器。此数据不包括独立 Web、PostgreSQL、操作系统，不代表任意 4K 输入、并发负载或 2 GiB 虚拟机的容量承诺。8 分钟任务超时仍然有效。

预览按播放位置保留活动配音和未来 3 秒内的配音；素材试听及成片播放器点击后才加载，不与实时预览争抢下载带宽。素材试听或成片开始播放会暂停实时草稿，开始播放草稿也会暂停其他播放器，防止两路声音叠加。已完成任务详情停止定时轮询，刷新和任务变更仍可更新结果。媒体请求失败后提供“重新加载预览素材”，播放按钮也会重新加载失败的媒体源；正常进行中的请求不会因点击播放而重新下载。缓冲期间暂停所有活动音轨和预览时钟，持续 30 秒未就绪时提示重试。

低 CPU 验收还修复了原生 `play()` 延迟启动时，墙钟先前进、继而反复校时暂停的问题：有活动音频时跟随其实际播放时钟，其次使用活动视频时钟；纯图片和定格尾帧才按墙钟推进。编码进程被系统或外部强制终止时，任务保留具体信号（如 `SIGKILL`）并失败，不发布半成品；重试创建新任务并复用冻结版本。相关回归真实执行终止和重试，不把 `SIGKILL` 自动判定成内存不足。

弱网验收使用浏览器限速（下载 1 Mbps、上传 0.5 Mbps、延迟 300 ms、禁用缓存），覆盖冷加载、转场、断网定位及恢复后的四条重叠配音。带宽不足时允许缓冲，不保证高码率原素材在 1 Mbps 下连续实时播放。尚未提供低码率预览代理、离线媒体缓存或自适应码率；真机与远程存储仍需单独验收。

390 CSS 像素、浏览器 CPU 六倍限速下，完整预览在约 605 秒观测到 600 秒终点，JS 堆峰值 55.3 MiB，无相关控制台错误或页面横向溢出。每秒采样中有 3 次处于缓冲；2,225 个活动音轨时钟样本相对时间线的偏移 P95 为 84 ms、最大 112 ms。它验证浏览器调度与原生媒体时钟，不是声卡输出的逐采样测量。1280 CSS 像素覆盖 CPU 限速与上述弱网同时启用时的冷加载、转场，另验收断网恢复；320 CSS 像素检查关键控制布局和六倍 CPU 限速下的片尾停止。

本轮页面提交的新 v2 成片归档成功，下载哈希与同版本原成片一致。五个关键帧（15、172、532、9000、17940）检查画面、淡化/擦除和中文样式，预览与导出 RGB 通道平均绝对差为 0.45–4.06 / 255；保留 H.264 的有损编码差异。导出音频八个窗口的音量与预期混音相比误差小于 0.2%。样例的 20 段配音最多四段同时叠加，另有视频原声，并非 20 路持续并发验收。

最终回归：58 项单元、54 项服务端与 HTTP 测试通过，另完成生产构建、类型与边界、格式和 62 项来源哈希校验。模型 API 始终关闭；没有新增基础设施、模型部署或数据库迁移。
