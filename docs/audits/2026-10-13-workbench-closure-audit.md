# 工作台闭环审查与 RunningHub 对照

审查日期：2026-10-13（Asia/Shanghai）。范围：图片生成/编辑、视频生成、参考声音克隆、API 工作流；继续使用托管模型 API，不增加本地 GPU、模型部署或微调服务器。

## 结论与证据范围

当前定位为可运行的本地开发底座。参数编辑、素材/声音保存、任务快照、提交历史、DAG 参数试运行已有实现；真实创作产出、可靠后台执行与账户数据管理尚未闭环。上轮完成的是无密钥功能范围，不能据此认为真实生成或上线验收已通过。

本轮依据当前源码、当前 README/验收记录，以及 RunningHub、fal、Replicate 的官方公开文档。内置浏览器安全策略拒绝读取本地页面，本轮未完成新的页面操作/截图验收；没有换用其他浏览器或 CDP 绕过限制。RunningHub 首页及部分文档直连超时，官方文档的相关内容通过搜索索引获取。没有登录 RunningHub、调用付费生成、验证其内部实现或取得私有服务端源码。REA 的一次公开首页场景捕获因 actions 参数校验未执行，未形成可用于结论的动态证据。

本轮不修改产品代码。审查中的生产要求是接通真实 API 前需要补齐的功能，不把按计划关闭的 API 当作当前本地范围的新故障。

## 现有严谨措施

- Zod 参数约束与统一能力目录；首期参数子集有明确边界。
- DAG 端口类型、循环和引用检查；每次运行保存独立快照。
- 任务事件与独立重试尝试；结果不确定时停止自动重试。
- IndexedDB 原子更新、同源标签 Web Locks 互斥；取消不会被当前探测请求的迟到响应覆盖。
- 已保存工作流/任务的素材引用删除保护。
- 未启用状态明确，没有用计划引用充当生成媒体。

这些保证仅覆盖当前本地实现。模型调用有效性、供应商去重、跨用户隔离、云端恢复和实际成本尚不在已验收范围。

## 首期必须补齐的五组能力（P0）

### 1. 服务端任务与供应商执行

- 建立持久 job、attempt、provider request、event 记录，以平台任务 ID 贯穿表单、任务中心、工作流和历史。
- 实现 fal 图片/视频、选定托管语音模型的 submit/status/result/错误转换；先验收各一条实际能力，再扩展目录。
- 记录供应商请求 ID。请求超时后先核对状态；重试提交必须依据供应商支持的幂等/查询能力设计，不能承诺普遍 exactly-once。
- 使用 Trigger.dev 等持久任务执行查询/归档；浏览器关闭不影响任务。webhook 验签、重复事件去重、漏回调后的补偿查询。
- 状态建议包含 submitting、queued、running、archiving、succeeded、failed、cancel_requested、cancelled、reconciling；保留供应商原始状态，映射不能丢掉取消或错误语义。
- 取消请求先进入 cancel_requested；最终可能确认取消，也可能生成已完成。不能直接抛弃晚到结果或据本地取消承诺未扣费。

验收：关闭页面后任务继续；刷新/重新登录能查询；超时、重复回调、服务重启、取消与完成竞争均有确定处理路径。

### 2. 文件与用户数据归属

- Better Auth 会话接入任务、素材、声音、工作流 API；每次读写均校验归属。
- 私有对象存储上传、下载签名、访问时效和来源白名单；向供应商提供其可访问的输入，不发送 `local-asset:` 或浏览器 `blob:` URL。
- 结果以流式方式复制/校验到自有存储，写入 asset 及其任务、节点、参数和来源关联。生成成功与归档完成分开处理。
- 归档失败可重试归档，复用已完成供应商请求，避免为下载失败重新付费生成。
- 本地数据迁移与导出要说明资源文件是否包含；当前 JSON 只有 ID，不能保证跨设备重现。

验收：原供应商链接到期后仍能查看/下载；换浏览器仍有历史；第二个账号不能读取他人文件、声音或任务。

### 3. 工作台交互与成果复用

- 工作台内绑定统一任务状态、进行中结果卡、成功预览、失败原因、历史；任务中心同步同一个任务 ID。
- 提交后能直接打开对应任务；不要求用户按提示手动搜索。
- 生成图片可直接“用于图生视频/继续编辑”；音频/视频可播放、下载、复制参数，结果统一进入资产库。
- 切换页面、刷新和任务完成通知应保持一致。成本与预计等待时间不能随意编造进度百分比。
- 语音模型锁定实际托管版本与 schema；按真实要求校验录音格式/时长/采样率，提供试听及参考声音管理。公开服务增加录音使用授权确认、私有访问和删除能力。

验收：用户从输入进入，能在平台内获得一个可用文件，并在下一次创作中直接复用。

### 4. 真实工作流执行

- 节点等待真实供应商结果与归档资产，执行后续节点；记录每节点请求 ID、资产、状态和成本。
- 固定本次运行的图版本与实际模型参数，明确默认值变化。
- 下游失败时允许从确认可复用的已完成节点继续，不重复生成成功的上游；删除/过期输入要有明确恢复指引。
- 首期验收“文本→图片→图生视频”与“参考声音+文本→语音”两条真实流程。

验收：传给视频 API 的确实是本次图片输出；下游失败后的恢复不会重复调用上游。

### 5. 成本边界与运维

- 服务端单用户并发/速率限制、单次任务预算、每日/全局花费上限和余额/额度检查。
- 保存供应商消耗与估算/实际费用的区别。内部内测可先人工额度，无需先做完整充值系统。
- 如收费，提交预占、执行后结算、失败按供应商实际费用规则释放/调整，并保证重放不会重复记账；不承诺所有失败都免费。
- 任务/供应商请求关联日志、失败分类、卡住任务告警、管理查询与核对、数据备份/恢复验证。
- 配置入口区分“变量已填写”“鉴权/模型访问已验证”“生成执行启用”。连通检查如会发起付费样本，需明确预算和动作。

验收：超出限制时拒绝提交；能解释一次失败是否花费、一次任务卡在哪里、由谁恢复。

## P1 与完整 RunningHub 范围

P1：少量精选模板、将已验证工作流发布为表单、一组模型支持的高级参数、结果对比/批量、项目文件夹、用户收费所需的充值与订单、后台管理。图片/视频/语音 API 节点已经是表单入口，没有必要先造通用“小程序平台”。

视频与克隆语音合成为带配音的 MP4，属于下一层成品交付能力。如果目标是直接交付配音视频，需要增加合成/音量/时长对齐与导出；如果首期目标是分别获得图片、视频和音频，这一项不阻塞基础闭环。

完整 RunningHub 的专业 ComfyUI 云运行、自定义节点生态、创作者社区/应用分发等能力是更大产品范围，应另立阶段。LoRA 训练和 GPU 管理不纳入当前全 API 首期，也不把未经本轮验证的模型训练功能列作 RunningHub 当前确定事实。

## 建议实现顺序

1. 云端持久数据与所有权、私有上传、任务协议与供应商模拟适配器；可先不使用模型密钥，通过受控 fixture 验证回调、重启、取消和归档失败。
2. 在同一服务端执行链上，各接通一个图片、一个视频、一个语音克隆模型；受控真实样本验收，接通工作台成功预览及资产归档。
3. 将已验证的执行链接入 DAG，完成两条真实模板、失败节点恢复、成果跨页面复用；补齐预算、限流与运维后小范围内测。
4. 根据真实使用数据增加模型参数/模板和发布表单，收费前完成订单、账本与退款/调整。

部署保持 Next.js + 托管 PostgreSQL + 私有 S3 兼容存储 + Trigger.dev + 模型 API。复用现有组件和状态/图校验逻辑；供应商 SDK 负责 API 协议，平台自研任务关联、归档、权限、计费与工作流业务规则。无需增加模型服务器。

## 交付门槛

1. 文生图和图片编辑获得真实可下载文件；图片结果可直接进入图生视频。
2. 文生视频/图生视频有正确的真实状态、播放与下载。
3. 参考录音能生成新文本语音，试听有效，结果可再次查看。
4. 浏览器关闭及执行服务重启后，任务仍能恢复到正确终态。
5. 重复提交/回调、超时核对、取消与完成竞争不会造成无说明的重复生成或记账。
6. 归档失败仅重试归档；供应商 URL 到期不影响已归档结果。
7. 任务和节点有错误定位与恢复入口；已有成功节点可复用。
8. 双账号隔离、预算/并发限制、备份恢复与真实供应商受控样本通过。

本轮只做审查，不执行这些后续开发，也不调用真实付费样本。
